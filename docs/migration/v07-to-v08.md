# Migration: v0.7 to v0.8

v0.8 keeps v0.7 workspaces readable. The default reader lazily adapts `.analysis/llm/analysis-document.json` when `.analysis/analysis.json` is absent.

Use explicit migration only when you want to materialize v0.8 aliases in an existing workspace:

```sh
cognianalysis dev migrate .
```

The migration is non-destructive. It does not delete LLM-authored v0.7 artifacts.

| v0.7 | v0.8 |
|---|---|
| `.analysis/data/code-map.json` | `.analysis/inventory.json` |
| `.analysis/llm/analysis-document.json` | `.analysis/analysis.json` via adapter |
| `.analysis/llm_tasks/*.md` | `.analysis/workpacks/*.md` |
| `.analysis/source_tiers/*.json` | audit-only |
| `.analysis/detail_reviews/*.json` | audit-only or shard input |
| `complete` | `complete-audit` |
| `deep-dive` | `deep` |

`complete` and `deep-dive` remain compatibility aliases during the v0.8 transition and print deprecation warnings when used through `analyze --mode`.
